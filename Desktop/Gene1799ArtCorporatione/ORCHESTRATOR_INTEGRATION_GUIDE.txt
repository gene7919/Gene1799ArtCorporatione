🧠 INTELLIGENT ROUTING LOGIC
════════════════════════════════════════════════════════════════════════════════

The Unified Orchestrator uses intelligent routing to determine the best provider:

1. MEDICAL QUERIES (domain: "medical")
   → Preferentially route to Azure alMedicochelante
   → Fallback to local medical agent if Azure unavailable
   → Final fallback to Ollama (Mistral)

2. SPECIALIZED QUERIES (domain: "code", "analytics", "security", etc.)
   → Route to matching local agent
   → Fallback to Ollama if local agent unavailable
   → Final fallback to Azure if all else fails

3. GENERAL QUERIES
   → Route to local Ollama (Mistral model)
   → Fallback to Azure if Ollama unavailable
   → Error if all providers offline

4. AGGREGATE QUERIES
   → Query all specified providers in parallel
   → Return combined results
   → Useful for comparing outputs from different AI systems

🔄 HOW IT COORDINATES SERVICES
════════════════════════════════════════════════════════════════════════════════

REAL-TIME HEALTH MONITORING
────────────────────────────
Every 5 seconds, the Orchestrator:
  1. Checks health of all 7 local services
  2. Checks health of Azure AI service
  3. Updates service status (healthy, degraded, unhealthy)
  4. Triggers events when status changes
  5. Adjusts routing based on available services

LOAD BALANCING
──────────────
  • Tracks response times for each provider
  • Calculates average response time
  • Routes new requests to fastest responding provider
  • Automatically avoids slow/failing services

FALLBACK STRATEGY
─────────────────
  • Primary: Route to best provider for query type
  • Secondary: Fallback to alternative provider if primary fails
  • Tertiary: Fall back to Ollama (always available locally)
  • Error: Return error only if all providers offline

METRIC TRACKING
───────────────
  • Tracks every request and response
  • Calculates success rate
  • Records which provider handled each request
  • Provides insights into system performance

🔧 CONFIGURATION
════════════════════════════════════════════════════════════════════════════════

The Unified Orchestrator is configured in orchestrator-unified.js:

Port Configuration:
  CONFIG.SERVER_PORT = 5050                    // Main orchestrator port
  CONFIG.LOCAL_SERVICES                        // All local service ports
  CONFIG.AZURE_SERVICE.port = 8001             // Azure AI port

Health Check Interval:
  CONFIG.HEALTH_CHECK_INTERVAL = 5000          // 5 seconds

Request Timeout:
  CONFIG.REQUEST_TIMEOUT = 30000               // 30 seconds

To customize:
  1. Edit orchestrator-unified.js
  2. Modify CONFIG object at the top
  3. Restart orchestrator: node orchestrator-unified.js
